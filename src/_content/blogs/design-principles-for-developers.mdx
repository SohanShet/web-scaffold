As a developer, having a basic understanding of design principles can significantly improve the quality of your work. It helps you collaborate better with designers, make informed decisions when implementing interfaces, and ultimately create better experiences for your users. You don't need to become a designer — you need enough shared vocabulary to catch problems before they ship.

> "Design is not just what it looks like and feels like. Design is how it works." — Steve Jobs

## Hierarchy and Layout

Visual hierarchy is about organizing elements in a way that guides the user's eye through the content. By using size, color, weight, and spacing effectively, you can emphasize important information and create a clear structure for your page. A screen with no hierarchy forces the user to read everything to find anything.

A few reliable levers for building hierarchy, in order of how much control they give you:

1. **Size and weight** — the biggest, boldest element on the screen is what people look at first.
2. **Color and contrast** — a single accent color on a primary action draws the eye more reliably than adding a second button of equal weight.
3. **Whitespace** — grouping related elements close together, and separating unrelated ones with space, communicates structure without a single border or divider.
4. **Position** — content near the top-left (in LTR layouts) gets scanned first; don't bury the primary action below three sections of marketing copy.

## Typography Matters

Good typography is essential for readability and aesthetics. Choosing the right fonts, line heights, and spacing can make a huge difference in how your content is perceived. Aim for a clean, legible typeface and maintain consistent spacing throughout your design.

| Property | Guideline | Why it matters |
|---|---|---|
| Line height | 1.4–1.6x the font size for body text | Tight leading makes paragraphs feel cramped and harder to track line-to-line |
| Line length | 45–75 characters per line | Lines that are too wide make the eye lose its place on the return sweep |
| Font pairing | One typeface for headings, one for body — at most two total | More than two typefaces on a page reads as inconsistent, not intentional |
| Type scale | A consistent ratio (e.g. 1.25x) between heading sizes | Arbitrary sizes ("this looks about right") accumulate into visual noise over time |

## Color With Intent

Color isn't decoration — it's a signaling system. Every extra color you introduce is one more thing users have to learn the meaning of.

- Reserve your brand's primary color for primary actions, not for every interactive element on the page.
- Use semantic colors consistently: red for destructive/error states, green for success, never swapped.
- Check contrast, not just taste — text on a background should meet at least a 4.5:1 contrast ratio for body copy (WCAG AA).
- Don't rely on color alone to convey state — pair it with an icon or label for users with color vision deficiencies.

## Consistency Over Cleverness

The fastest way to make an interface feel trustworthy is to make it predictable. A button that looks the same and behaves the same everywhere in your product is worth more than ten uniquely styled one-off buttons that each took longer to build.

```css
/* One button component, driven by variants —
   not five hand-tuned one-off buttons */
.btn {
  padding: 0.5rem 1rem;
  border-radius: 0.5rem;
  font-weight: 600;
  transition: background-color 150ms ease;
}

.btn--primary {
  background: var(--color-primary);
  color: white;
}

.btn--primary:hover {
  background: var(--color-primary-dark);
}
```

When you catch yourself writing a one-off style for a single screen, ask whether it's solving a real problem on that screen — or whether it's a sign the shared component needs a new variant instead.

## Conclusion

None of this requires a design degree. Pay attention to hierarchy, keep typography consistent, use color deliberately, and default to reusing existing patterns before inventing new ones. Those four habits alone close most of the gap between "a developer built this" and "a design team built this."
